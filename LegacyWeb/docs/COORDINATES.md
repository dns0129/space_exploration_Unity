## 坐标约定

导航继续使用双精度的恒星系统内位置。`systemId` 选择系统原点；系统之间的原点位移来自 `world.systems[].positionLy`，以光年表示。系统内位置和天体半径保持现有世界单位：`1 世界单位 = world.unitsKm km = 6,371,000 m`。远距离目标、跃迁和轨道预览在这个坐标系中计算，不把光年级位置送入 Rapier。

附近物理统一使用米、秒、米/秒。局部轴与系统的右手世界轴平行（+X 向右、+Y 向上、默认前方 −Z）；没有每帧旋转的切平面轴，人物的竖直方向单独取所属天体的径向。物理原点是可移动的计算原点，不是行星中心，也不是存档位置。

令 `S = world.unitsKm × 1000`，`P` 为系统内世界位置，`C` 为天体中心，`r` 为天体相对位置（米），`o` 为局部原点的天体相对位置（米）：

```
r = (P − C) S
x_local = r − o
P = C + (x_local + o) / S
```

远处空间帧采用同样的原点差分原则。世界位置只作为导航和兼容接口；进入附近物理后，体相对米制位置保留为独立的精确状态，避免反复从 AU 级位置相减来积分米级位移。转换集中于共享空间帧模块。

## 浮动原点

活动对象离局部原点达到 **256 m** 时，把同一个位移 `Δ` 从局部人物、附近飞船、地形碰撞体和局部相机位置中减去，并将帧原点加上 `Δ`。阈值集中于 `FLOATING_ORIGIN_DISTANCE_M`。因此任意两点的距离不变：

```
(x₁ − Δ) − (x₂ − Δ) = x₁ − x₂
```

这是坐标平移，速度、四元数朝向和碰撞几何不改变。重定位在物理步进边界完成，场景与物理体使用同一帧；渲染前根据最新帧产生局部位置。

## 太空、着陆、徒步和起飞

接近固体天体时，附近帧选择该天体；着陆及徒步固定使用所属天体，避免因为人物/相机微动改选另一天体。重力向量为 `−g r / |r|`，不使用恒定世界向下。

当前游戏的天体中心和固体地形是静态轨道示意，物理中心速度与角速度均为零。观测模式的模型自转和飞行中的云层漂移属于视觉动画，不改变固体地形的物理参考系。这保持现有影像、地形采样、着陆和碰撞的位置关系；本次没有添加真实星历或行星自转。

一般运动参考系应使用：

```
P = C + R r / S
v_universe_mps = V_center + R (v_relative + ω × r)
v_relative = R⁻¹ (v_universe_mps − V_center) − ω × r
```

`R` 是体轴到系统轴的旋转，公式中的 `ω` 是体轴中的角速度；帧接口的 `angularVelocityRadps` 使用系统轴表达，先经 `R⁻¹` 转换后参与叉乘。当前 `R` 为单位旋转、`V_center = 0`、`ω = 0`，所以切换参考系只转换单位与原点，不额外叠加速度。将来添加物理自转时必须同时更新这些位置/速度转换和共享地形姿态，不能把观测动画速度直接加给人物或飞船。

## 可见地形与碰撞

附近地表、脚底高度和 Rapier 碰撞使用同一米制位置来源及共享高度场。人物附近 **96 m × 96 m、间距 0.5 m** 的可见精细网格与碰撞网格一致，随人物移动更新；外部完整球面继续封闭远处地平线。近景世界绘制使用米制相机，避免将毫米级深度精度交给太阳系尺度的投影。

人物碰撞采用圆角胶囊。坡面上的胶囊接触会让径向脚底高于该点解析地形，存档允许落地状态最多 0.20 m 的正向接触间隙；地下容差仍为 0.015 m，不能用恢复存档将人物放入地形。

跟随相机从人物眼睛到插值后的镜头位置，对同一个 Rapier 地形网格做半径 **0.20 m** 的球形扫掠，并保留 **0.02 m** 接触间隙，遇到山坡时回缩镜头。第一人称的零长度查询也使用真实网格处理接触。查询排除人物胶囊，不推进物理时间、不改变人物速度；浮动原点平移及恢复后立即使用当前局部米制坐标。镜头不再使用另一个解析地面高度来修正位置。

## 存档与兼容

存档保留 `systemId`、系统内世界位置/速度和必要的体参考信息。新增 `coordinateVersion: 1` 与 `referenceFrame`：太空帧为 `{ kind: "system" }`；体参考帧为 `{ kind: "body-fixed", bodyId, radialM }`。`radialM` 以米保存飞船相对天体中心的位置，轴与系统轴平行，避免存取期间丢失近处位置精度；兼容的 `position` 仍保存系统内世界位置。两者必须在浮点舍入允许范围内一致，损坏的数据不会被静默用另一个位置替代。

徒步位置继续保存为相对停泊飞船的米制偏移 `walking.offsetM`，不保存 Rapier 的瞬时局部平移或浮动原点。速度保持系统世界轴单位/秒，步行速度保持米/秒；当前静态体参考系不额外叠加天体速度。恢复时先在双精度坐标中将原点移至人物附近，再生成 Float32 地形和碰撞体，重新建立接触状态。渲染同时检查地形对象和修订编号，防止新物理世界从相同编号开始时沿用旧网格。

旧版压缩世界存档、旧轨道布局以及旧高度场的迁移继续先验证旧状态，再迁移至当前地形；迁移是幂等的。损坏的参考系、跨系统天体或不一致的位置被拒绝。

## 验证边界

动力学、参考系、重定位和存档测试由 `npm run test:server` 运行；网站浏览器与离线包分别由 `npm run test:site` 和 `npm run test:offline` 验证。使用 Node.js 24，以支持项目直接导入的 TypeScript 文件。

本地测试和导出的下载包不证明公开网站已经更新。公开版本以 GitHub Actions 部署结果及公开 `version.json` 中的提交为准。

本次测试场景、误差断言和离线包校验见 [SCALE-VALIDATION.md](SCALE-VALIDATION.md)。

Rapier 目前处理人物与地表碰撞；24 m 的停泊飞船模型保留现有返舱距离判断，没有新增完整船体碰撞网格。相机对船体仍沿用可见模型的射线回缩，地形则采用真实碰撞网格的球形扫掠。
